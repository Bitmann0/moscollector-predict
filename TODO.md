# Ближайшие задачи команды

## ML: текущая работа (`feature/catalog-aware-ml`)

- [x] Довести [отдельную очередь объектов](reports/GUARD_REVIEW_QUEUE.md) для ручной проверки риска записанного охранного сигнала СМВУ завтра: кандидаты только по сегодняшним данным, событийная v2-разметка, фиксированный дневной лимит, честная подпись результата.
- [x] Проверить выдачу на исторических днях против воспроизводимого правила и показать число неизвестных исходов; не выдавать старую модель `C` за этот сценарий.
- [x] Пакетно пересчитывать v2-кэш после добавления новых дней и явно останавливать выдачу, если кэш устарел.
- [x] Добавить [узкую недельную очередь повторяющихся охранных сигналов](reports/GUARD_WEEKLY_INSPECTIONS.md) с правом воздержаться, суточным запасом до окна прогноза и паузой между повторными рекомендациями. Сверить выдачу сервиса с полным историческим бэктестом.
- [ ] После поступления новых недель проверить замороженную недельную политику и решения диспетчера; исследованные годы не являются слепым тестом.
- [ ] Сделать инкрементальное обновление событий и объектных признаков нового дня с замером полного цикла ≤300 секунд. Текущий полный пересчёт истории слишком долгий.

## ML: второму специалисту, отдельно от очереди C

- [ ] По [мини-ТЗ второму ML-разработчику](docs/SECOND_ML_BRIEF.md) в своей ветке от `feature/catalog-aware-ml` перепроверить `D` и `A_link` на полной дневной очереди, при сохранённом пороге и лимите в **каждые** сутки. Отдельно посчитать новые эпизоды, повторы, число рекомендаций за месяц и сравнение с простым правилом. Результат: воспроизводимый код, отчёт и решение «показывать / оставить экспериментом» для каждой головы.
- [ ] После этого проверить температурный [почасовой бэктест другой ветки](https://github.com/Bitmann0/moscollector-predict/tree/feature/episode-hourly-backtest): физический смысл 0/1/2 °C, покрытие по обновлённому справочнику, ценность для диспетчера.

## Бэкенд: свобода реализации, обязательный результат

Детали и приёмка — в [передаче бэкендеру](docs/ML_BACKEND_HANDOFF.md). Бэкендер выбирает фреймворк, схему PostgreSQL, фоновые задачи, авторизацию и UI. Нужны разрешённые к показу головы, постоянное хранение прогнозов и решений, подтверждение заявки человеком, идемпотентная загрузка новых данных, свежесть/ошибки в API и замер полного CPU-цикла в Linux. Смысл меток, модели и пороги согласуются с ML.
