Четыре окна по 28 суток. В протоколе ошибочно указано начало 04.09: стенд отсчитывает 4 × 28 = 112 суток назад от `--end 2025-12-31`, и первый день получается 11.09. Окна и правило решения от этого не меняются.

| D | правило, порог 70 % | 80 | 51 | 25 | 63,8 % | 22 |

Поймано эпизодов правилом D по окнам: 11, 3, 2, 6; моделью D — 0 во всех четырёх. У A_link модель впереди во всех четырёх окнах: 336, 312, 314, 342 против 7, 0, 1, 0.

Условия протокола для D выполнены все: эпизодов у правила больше (22 против 0), нижняя граница выше (63,8 % против 0), перевес во всех 4 окнах из 4. Для A_link не выполнено ни одно.

Вспомогательная пара без порога показывает то же для D: правило 96 попаданий из 159 (60,4 %) и 45 эпизодов, модель 119 из 271 (43,9 %) и 33 эпизода. 184 из 271 рекомендаций модели приходятся на эпизоды, которые уже идут.

## Ограничения

- **Данные разные.** Валидация считана на локальной сборке `U:\hackathon\data` от 20–23.09; отчёт 42 дней — на бандле Александра. Хеши `daily_channel`, `episodes` и `sensor` не совпадают, совпадает только `channels`. Направление вывода на обоих наборах одно, но числа между отчётами сравнивать напрямую нельзя.
- **Даты 2025 года не слепые.** Они входили в прежнюю оценку модели; нетронутым было только сравнение с правилом в этом стенде.
- **Unknown у D велик**: 25 из 80 рекомендаций правила. Промах у D засчитывается только при телеметрии за все 7 будущих суток, поэтому 63,8 % — нижняя граница.
- **Метка — прокси из той же телеметрии.** Правило «были плохие состояния — будут ещё» здесь сильный базовый вариант по построению. Поэтому решение опирается на новые эпизоды, а не только на precision.

## Воспроизведение

Из папки `ml/`:

```bash
python scripts/audit_second_ml.py --mode historical --data-root /path/to/data \
  --splits 4 --test-days 28 --end 2025-12-31 --threads 12 \
  --output reports/rule_vs_model_2025h2.json
```

Windows 11, Python 3.12, 12 потоков, 1 350 секунд wall time.
