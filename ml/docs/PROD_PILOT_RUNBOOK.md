# Пилотный продовый сценарий

Единственный ML-сценарий, который сейчас разрешено показывать как рабочую
ручную рекомендацию, — недельная очередь повторяющихся охранных сигналов.
Она не создаёт заявку автоматически и говорит о продолжении **записанной**
активности охранного контура.

## Перед запуском

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -c "from mkl import api; from fastapi.testclient import TestClient; print(TestClient(api.app).get('/ready').json())"
```

Ожидается `status=ready`, `event_cache_version=2` и одинаковые
`data_last_day`/`event_cache_through`. `stale`, `missing_data` и `error`
останавливают выдачу до обновления данных.

## Расчёт понедельника

```text
GET /ready
GET /api/v1/guard-weekly-inspections?asof=YYYY-MM-DD
```

`asof` должен быть понедельником. В ответе сохраняются весь JSON,
`schema_version`, `model_version`, `result_status`, `data_snapshot` и каждая
строка с `recommendation_id`. Повторный расчёт того же понедельника и объекта
должен делать upsert по `recommendation_id`, а не создавать новую рекомендацию.

`result_status=empty_valid` — успешный расчёт без кандидатов. Его нельзя
показывать как ошибку и нельзя подменять прошлой выдачей.

Сам endpoint также блокирует расчёт при `missing_data`, `stale` или `error`,
поэтому проверка `/ready` перед показом остаётся обязательной частью healthcheck,
а не единственной защитой.

## Решение диспетчера

Для каждой рекомендации сохраняются автор, время, действие (`check`, `defer`,
`reject`), комментарий и фактический исход (`confirmed_event`, `sensor_fault`,
`normal_activation`, `no_event`, `unknown`). История не перезаписывается.
Подтверждённая заявка появляется только после решения человека.

## Контроль через неделю

ML сопоставляет окно `D+2..D+8` с записанными охранными событиями, считает
precision, recall, unknown и уникальные серии. Пока нет фактических решений
диспетчера, метрика остаётся прокси и не объявляется выполнением ТЗ.

Остальные головы, включая модель начала новой серии, остаются скрытыми из
рабочего списка до новых данных и отдельного прохождения
[продуктового фильтра](ML_PRODUCT_GATE.md).
