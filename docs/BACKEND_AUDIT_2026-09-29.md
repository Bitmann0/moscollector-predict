# Ревизия backend на 29.09.2026

База ревизии: `main` на `7b56ce8` с уточнениями OpenAPI и документации в `842629a`.
Проверены маршруты FastAPI, сервисы, модели и миграции, CI, контракты и таблица
трассировки ТЗ. Локально: 568 тестов прошли, 16 пропущены (12 LDAP, 3 PostgreSQL,
1 справочник заказчика); Ruff, генерация контрактов и сборка frontend прошли.
Docker на этой машине недоступен. «Риск» ниже означает вывод из кода, который ещё
нужно воспроизвести на PostgreSQL; «дефект» — поведение прямо следует из кода.

## Требования, которые backend один не закроет

Таблица `docs/submission/11-traceability.md` верно оставляет частичными: прогноз
подтверждённого отказа/пожара/подтопления/проникновения; целевые precision и recall;
сравнение рекомендаций с фактическими решениями; обучение по журналу ОДС; приём через
очередь сообщений и формат Приложения 1. Нужны подтверждённые инциденты, ремонты,
допуски и реальные решения, которых заказчик не предоставил, затем отдельная
валидация модели. Backend должен хранить происхождение и качество этих данных, но не
выдавать прокси-метки за подтверждённый исход.

## Проверки перед заявлением о готовности

1. Поднять чистый Linux-стенд с PostgreSQL и LDAP, пройти миграции, импорт реальных
   справочников, полный приём, прогон ML в `real`, перезапуск, резервное копирование
   и восстановление. На этой машине Docker недоступен; 16 тестов локально пропущены.
2. Конкурентные тесты PostgreSQL для приёма, заявок, прочтения уведомлений, настроек
   и повторного расчёта; fault injection между коммитом БД и публикацией событий.
3. Нагрузочный тест у пределов 200 МБ/5 000 строк, профиль RSS, время ответа и
   блокировки БД; проверка порогов на данных масштаба 10 млн событий.
4. Сверить OpenAPI с реальными ответами JSON/XML и ошибками, обновить устаревшие
   утверждения `docs/MVP_TASKS.md` и разделов сдачи. Например, таблица ТЗ всё ещё
   утверждает, что выход не отзывает cookie, хотя `security.py` отзывает `jti`.

Критерий завершения: для каждого P0/P1 есть интеграционный тест и измеренный
эксплуатационный предел; для P2 либо реализовано исправление, либо записано
согласованное ограничение с мониторингом. Отдельно документируются ограничения
исходных данных и фактическое качество моделей. Слово «без багов» ни тесты, ни
ревизия доказать не могут.
