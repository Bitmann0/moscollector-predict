# OpenAPI и ручная проверка API

После запуска сервиса интерактивная документация доступна по `http://localhost:8000/docs`,
а машиночитаемая спецификация — по `http://localhost:8000/openapi.json`. Swagger UI показывает
схемы запросов, ограничения полей, коды ошибок и позволяет выполнять запросы через **Try it out**.

## Авторизация в Swagger UI

1. Выполните `POST /api/v1/auth/login` с логином роли и паролем из `.env`.
2. Браузер сохранит HttpOnly cookie. Последующие операции через тот же Swagger UI автоматически
   выполняются от имени этой роли.
3. Внешние системы передают заголовок `X-API-Key` со значением `INTEGRATION_API_KEY`; эта роль
   предназначена для загрузки данных и изменения статуса заявок.

Права проверяются на каждом защищённом маршруте. Неподходящая роль получит `403`, отсутствующая
или просроченная сессия — `401`, конфликт одновременного изменения заявки — `409`.

## Быстрый сквозной сценарий

1. Войдите как `admin`.
2. При наличии реальных CSV поместите их в `data/raw/` и вызовите `POST /api/v1/reference/sync`.
3. Вызовите `POST /api/v1/admin/run-daily` с датой демонстрационного окна.
4. Откройте `GET /api/v1/forecasts`, затем карточку `GET /api/v1/forecasts/{id}`.
5. Сохраните решение `POST /api/v1/forecasts/{id}/decision`; причина должна быть допустима для
   выбранного действия, что можно проверить через `GET /api/v1/reason-codes`.
6. Создайте черновик заявки и меняйте статус через `POST /api/v1/work-orders/{id}/transition`,
   передавая текущий `expected_status`.

События можно загрузить JSON-пачкой (`POST /ingest/events`) или CSV/XLSX (`POST /ingest/events/upload`).
Точная дедупликация использует весь нормализованный кортеж события, поэтому повторная загрузка
безопасна. Результат каждой загрузки показывает принятые, повторные, отклонённые и вышедшие за
демонстрационное окно строки.
