# МосКоллектор — предиктивное обслуживание

Веб-сервис для раннего выявления деградации датчиков СМВУ. Первый MVP анализирует
частоту событий, тревожность, короткие повторные срабатывания («дребезг») и стабильность
значений, формирует прогноз риска на 24 часа и позволяет создать черновик заявки на
превентивное обслуживание.

> Текущий алгоритм — объяснимый baseline без учителя. Он нужен для проверки полного
> продуктового контура на предоставленном примере. Для подтверждения целевых метрик
> Precision > 0,7 и Recall > 0,5 необходимы размеченные журналы неисправностей и ремонтов.

## Быстрый запуск

Требования: Python 3.11+.

```bash
make install
make test
make dev
```

Откройте <http://localhost:8000>. Документация REST API доступна на
<http://localhost:8000/docs>.

CSV-файлы из `dataset.zip` уже могут находиться в `data/raw/`. Если репозиторий клонирован
заново, распакуйте туда:

- `журнал_событий_пример.csv`;
- `справочник_каналов_датчиков.csv`;
- `справочник_объектов_диспетчер.csv`.

Исходные выгрузки, архивы, PDF ТЗ и локальная SQLite-база исключены из Git. Это защищает
репозиторий от тяжёлых файлов и случайной публикации рабочих данных.

## Что уже работает

- загрузка и валидация CSV СМВУ;
- построение признаков по каждому каналу;
- объяснимый риск отказа с горизонтом 24 часа;
- дашборд, схема объектов, фильтрация и журнал прогнозов;
- создание черновиков заявок вручную и автоматически для высоких рисков;
- REST API и Swagger/OpenAPI;
- SQLite-журнал заявок;
- модульные и API-тесты.

## API

- `GET /api/v1/health` — готовность и свежесть данных;
- `GET /api/v1/summary` — показатели дашборда;
- `GET /api/v1/forecasts` — прогнозы с фильтрами;
- `GET /api/v1/forecasts/{channel_id}` — карточка риска;
- `GET /api/v1/maintenance-requests` — журнал заявок;
- `POST /api/v1/maintenance-requests` — черновик по прогнозу;
- `POST /api/v1/maintenance-requests/auto` — черновики для high/critical.

Подробности архитектуры и дорожная карта находятся в [docs/architecture.md](docs/architecture.md).
