# Узкая еженедельная очередь по повторяющимся охранным сигналам

25.09.2026. Ситуация для диспетчера: одни и те же охранные датчики подают
сигнал много дней подряд. Вместо ежедневных предупреждений с долей записанных
попаданий около 22% сервис может **воздерживаться**, а по понедельникам
предлагать плановую проверку нескольких объектов с сильной историей повторов.
Это поиск продолжающейся активности охранного контура, **не прогноз нового
проникновения** и не подтверждённый дефект датчика.

## Фиксированная политика выдачи

- После закрытия понедельника `D` берём только объекты, которые сейчас стоят
  на охране; последнее сообщение о состоянии должно быть не старше 7 суток.
- Требуем записанный охранный сигнал при охране минимум в **4 из предыдущих
  7 календарных дней**. Если таких объектов нет, список пуст.
- Ранжируем по числу дней с сигналом за неделю, затем месяц и давности
  последнего. Не более **4 объектов в неделю**. Объект, рекомендованный за
  последние 14 дней, повторно не выдаём как новую рекомендацию.
- Целевое окно: **среда через следующий вторник, `D+2..D+8`**. Оно начинается
  не раньше чем через сутки после конца понедельника. Соседние недельные
  окна не пересекаются.

Новая выдача живёт в отдельном API:

```text
GET /api/v1/guard-weekly-inspections
GET /api/v1/guard-weekly-inspections?asof=2025-06-16
```

Ответ содержит дату расчёта, окно прогноза, число объектов с признаками,
число подходящих и отсеянных, политику, объекты с названиями, историю сигналов
и `case_key` для объединения повторов. `priority_score` задаёт только порядок,
**не вероятность**; действие — ручная плановая проверка, без автозаявки.
Для последнего понедельника набора, 29.06.2026, кандидатов с четырьмя
тревожными днями не оказалось, и API вернул **пустой список**, а не четыре
слабых предупреждения.

## Ретроспективная проверка полной очереди

Считаем записанный сигнал СМВУ при охране в окне `D+2..D+8`. Если в будущем
не хватает телеметрии, исход помечается неизвестным; выбранные строки
остаются в знаменателе. Единица результата — **рекомендация объект-неделя**.
Эпизоды отдельно объединяются, если между днями сигналов одного объекта не
более семи суток. Состояние охраны на момент самого сигнала определяет v2-метка.

| Период | Рекомендаций | С записанным сигналом | Неизвестный исход | Разных пойманных серий |
|---|---:|---:|---:|---:|
| Фев–дек 2023 | 15 | 13 | 0 | 11 |
| 2024 | 27 | 19 | 3 | 17 |
| 2025 | 23 | 16 | 2 | 14 |
| Янв–июнь 2026 | 14 | 11 | 0 | 9 |
| **Всего** | **79** | **59 (74,7%)** | **5** | **51** |

Это около **двух рекомендаций в месяц**. Они касались 20 объектов. С учётом
14-дневной паузы 51 из 59 записанных попаданий относится к разным сериям,
а не к повторному счёту одной и той же недели. Среди всех текущих кандидатов
за этот срок было **1540 положительных объект-недель**; выдача нашла
**59/1540 (3,8%)**. Это намеренно узкий список плановых проверок, не система
массового обнаружения тревог. Базовая доля положительных объект-недель в
проверенных годах была около 25–31%, так что выбранная очередь существенно
обогащена будущими записанными сигналами.

Ограничение после выбора политики: порог «4 дня» и пауза 14 дней исследованы
на этих же годах. Это **ретроспективная, не слепая** оценка. Результат 74,7%
нельзя объявлять выполнением ТЗ: целевая метка — запись системы, полнота
3,8%, реальные проникновения не размечены. Чтобы проверить полезность,
нужно заморозить политику и ждать новых недель и решений диспетчера.

## Проверка, нужна ли здесь ML-модель

LightGBM, обученная только на 2023–2024 годах на тот же семидневный исход,
при том же пороге истории и лимите 4 в неделю на 2025–2026 годах нашла
**39/50** записанных попаданий — **столько же, сколько правило (39/50)**
до применения паузы. На всей очереди без порога она тоже не выиграла:
180/304 против 181/304. Поэтому рабочий порядок оставлен простым и
воспроизводимым. Модельный результат не подменяется метрикой правила.

## Добавление данных и воспроизведение

API использует объектный фичестор и v2-кэш событий. Он проверяет свежесть
кэша для понедельника расчёта и отказывает явно, если события ещё не
обработаны. Пакетное обновление новых дней уже поддержано; быстрый
инкрементальный пересчёт всего фичестора ещё нужен для ограничения 300 секунд.

```powershell
python scripts/build_intrusion_eventtime_labels.py
python scripts/exp_guard_longer_horizon.py
python scripts/exp_guard_weekly_repeats.py
python scripts/exp_guard_weekly_model.py
python -m pytest tests/test_guard_weekly.py -q
```
