# Очередь объектов для ручной проверки охранного сигнала СМВУ

25.09.2026. Это отдельная от старой головы `C` выдача. После окончания суток
`D` сервис выбирает до четырёх объектов для проверки в сутки `D+1`. Цель —
**записанный сигнал СМВУ из набора охранных тревог, когда последнее достоверное
состояние на момент сигнала — «На охране»**. Наличие сигнала не подтверждает
проникновение человека. Очередь не создаёт заявку на выезд автоматически.

## Как формируется выдача

Кандидат берётся из объектного фичестора на конец `D`: последнее известное
состояние — «На охране», сообщение о нём не старше семи суток. Завтрашняя
телеметрия не участвует ни в отборе, ни в ранжировании. На тестовых периодах
это около 31 объекта в день. Для каждого кандидата считаются дни с записанной
тревогой при охране за последние 7 и 30 календарных дней и давность последней
такой тревоги. Сначала идёт больше тревожных дней за неделю, затем за месяц,
затем более свежий сигнал; равные оценки разрешает ID объекта.

Число `priority_score` — **только относительный порядок**, не вероятность
тревоги и не вероятность реального происшествия. В ответе есть название
объекта, возраст сообщения об охране, числа дней с тревогами и основание
ранжирования. Когда за 30 дней не было записанной тревоги, основание явно
помечено как слабое. Выдача отделена от старого `C` и от API заявок:

```text
GET /api/v1/guard-signal-priorities?asof=2026-06-30&budget=4
```

Проверены бюджеты 1 и 4 объекта в сутки. На последнем дне данных
(`2026-06-30`) из 60 объектов с признаками подходят 32; API вернул четыре
объекта, HTTP 200, локально около 0,18 с вместе с вызовом тестового клиента.
Окно выдачи — 2026-07-01 ... 2026-07-02. Метки исхода за это окно в
предоставленном наборе нет.

## Сколько попаданий было на прошлых днях

Три уже исследованных 90-дневных блока 2025 года, всего 270 дней. Исход
положителен по событийной v2-разметке. Выбранные объекты с неизвестным исходом
остаются в знаменателе; «попадание» означает только **записанный** сигнал.

| Период | Предложено проверок | Записано попаданий | Исход неизвестен |
|---|---:|---:|---:|
| 05.04–03.07.2025 | 360 | 89 | 20 |
| 04.07–01.10.2025 | 360 | 91 | 19 |
| 02.10–30.12.2025 | 360 | 57 | 27 |
| **Всего** | **1080** | **237 (21,94%)** | **66** |

Отдельная проверка той же очереди ранее дала расширенной LightGBM
243/1080 (22,50%), то есть на шесть попаданий больше. Парный интервал
разницы включает ноль; убедительного выигрыша ML над правилом нет.
Чтобы проверить модель, которую проще перенести в сервис, мы обучили
LightGBM только на объектных признаках и этих четырёх счётчиках истории,
без сырых событий и будущих полей. На тех же блоках она дала **227/1080
(21,02%)**, а при одной проверке в день **73/270** против **88/270** у
правила. Выбор рабочего правила основан на этой проверке, а не на тезисе,
что любая ML-модель бесполезна.

Это не новый слепой тест: периоды 2025 года уже использовались в экспериментах.
Результат измеряет повторы и впервые возникшие сигналы вместе. Для первых
сигналов после спокойной недели точность ранее была около 7%; сервис не
обещает обнаружить каждое новое происшествие заранее. Прогноз ближайших
суток не гарантирует 24 часа запаса до конкретного сигнала.

## Новые данные и граница работоспособности

`scripts/build_intrusion_eventtime_labels.py` строит v2-кэш из событий и
актуального объектного фичестора; конечную дату берёт из добавленных дней.
Очередь проверяет версию и дату кэша. Если в фичестор поступил новый день,
а события ещё не обработаны, API возвращает ошибку вместо устаревшего списка.
На текущей версии полный пересчёт истории остаётся пакетным; инкрементальное
обновление нового дня и постоянный журнал решений диспетчера — следующие
задачи сервиса.

Воспроизвести:

```powershell
python scripts/build_intrusion_eventtime_labels.py
python scripts/backtest_guard_review_queue.py
python scripts/exp_guard_simple_model.py
python -m pytest tests/test_guard_queue.py -q
```

Числа сохранены в [проверке правила](guard_review_queue_backtest.json),
[сравнении простой ML-модели](guard_simple_model_experiment.json) и
[предыдущем сравнении с расширенной моделью](INTRUSION_OPERATIONAL_QUEUE.md).
